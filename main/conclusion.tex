\chapter{Conclusion and Open Questions}
\label{chap:conclusion}

\section{Summary}
\label{sec:concl-summary}

This thesis brought model-based relational testing to AArch64, including fuzzing of Arm-specific
features. We ported \revizor{} to AArch64 with a native-execution contract executor, added headless
fuzzing of remote cores, and modeled the Pointer Authentication and Memory Tagging extensions
(\autoref{chap:port}). We identified a limitation of the priming validation step, present in
\revizor{} since its inception, proved that it discards a class of real leaks, and gave a
source-agnostic detector in the black-box spirit of \revizor{}. It reports leaks originating in
other, possibly unknown microarchitectural structures while observing only the L1D. Every violation
it reports lets a co-located attacker distinguish two inputs the contract deems equivalent, simply by
running a fixed program after the victim and then measuring the L1D cache. Each of its two
localizers is optimal for what it returns (\autoref{chap:priming}). Speculative-exception fuzzing reaches the transient condition
violations behind PACMAN and TikTag without faulting the test case, aiming for attacker-valuable
leakage (\autoref{chap:precond}).

Together these uncover two new speculative covert-channel leaks on production Arm cores, one in the
canonicality and alignment checks of a pointer (\autoref{chap:canon}) and one in Pointer Authentication's sign
extension, which exfiltrate information across privilege and virtualization boundaries
(\autoref{chap:eval}). Used as a covert channel, and given an assumed control-flow hijack, the address-validity leak
recovers a complete RSA-2048 private key through OpenSSL (\autoref{app:poc-openssl}). Speculative-exception fuzzing also rediscovers TikTag on the
Cortex-X3, and on an Intel Alder Lake core the source-agnostic detection surfaces the known
AfterImage prefetcher leak, which shows the method is not Arm-specific. The proof-of-concept
artifacts behind these results are described in \autoref{appendix:pocs}.

\section{Open questions}
\label{sec:concl-open}

\paragraph{Detection for a general follow-up program.}
The extended contract violation of \autoref{chap:priming} is defined against an arbitrary follow-up
program $Q$, yet the detection construction realizes $Q$ only as the victim program $P$ replayed
over a static set of inputs. Generalizing the construction to an arbitrary
observing program $Q$, while keeping efficient fuzzing cost, would widen the class of
cascaded leaks the method can reach. How to do so efficiently remains open.

\paragraph{The secure / non-secure boundary.}
A necessary condition for crossing the secure boundary holds on our hardware: an EL3 world
switch does not by itself flush the normal-world branch-target buffer, which indicates that the BTB channel
is feasible across secure-world switches (\autoref{app:poc-smc}). Whether the channel actually crosses to a secure-world victim, which requires a
trusted-execution vehicle we did not have, remains open.
